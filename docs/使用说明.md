# 使用说明

1. 在侧边栏点击“导入网页对话”，选择 DeepSeek 官方导出的完整 JSON。
2. 选择对话与分支末节点，核对末尾原文。多个分支未能唯一确认时必须明确选择。
3. 选择 DSH 已登记工作区、已配置模型的会话作为设置来源。若列表为空，先在原生新会话页选好模型并打开会话，再回到导入页；无需发送测试消息。
4. 点击“本地预演”。这里不调用模型生成内容，显示的是原生计量估算和首次预计达到阈值的位置，不是网页端真实窗口复原。
5. 核对附件状态，可按原附件标识补入本体。只有元数据时不声称已经读取附件。
6. 勾选确认后准备。达到阈值才会产生摘要调用并计费；其余历史助手消息直接采用原文，历史工具不执行。
7. 准备经过原生回读、上下文与索引核验后，自动打开接续会话。第一条新消息由你发送。

## 工具与记忆

输入框的“对话 · RAG”表示只声明会话专属 `memory_search`。点击可切换工程模式，等待回复和工具执行结束后再切换。原生权限及审批不变。

原文是检索依据，角色、时间和节点随结果返回；旧记录不构成当前指令。不会每轮预检索，也不会自动提炼人格。新消息先保存，再自动增量索引；向量故障时聊天原文不丢失，检索明确降级为全文。

## 压缩与任务

使用 DSH 原厂算法及默认摘要。当前原厂模板偏英文工程检查点；没有额外20轮逐字引用或自定义情感栏目。上下文窗口、输出预留、压缩余量与保留尾部共同决定有效阈值，不按累计账单 token 触发。

“任务与设置”可暂停、取消、继续或重试。未知模型调用结果会等待检查，明确重试可能重新计费。每日导入摘要默认额度为200万输入／20万输出 token；原生聊天及会话就绪后的压缩单独由 DSH 管理。

## 数据与移除

在“任务与设置 → 存储位置”中配置 `dataDir` 与 `modelCache`。优先使用官方配置编辑器；0.2.1-rc.3 桌面端若报告缺少根 Include，插件只保存自己名下的启动位置文件，并明确提示正常重启后生效，不改写宿主文件。启动位置文件在默认数据根目录下 `locations/<profile>.json`。公开默认数据根目录为 `$DSH_HOME/conversation-bridge`；未设置 DSH_HOME 时为 `~/.dsh/conversation-bridge`。安装目录可任意放置，数据不写入安装包目录。

数据根目录含 `registry.sqlite`、`imports/`、`archives/`、`conversations/`、`models/` 和 `exports/`。每个接续会话的记忆库、来源、检查点及新经历位于 `conversations/<ID>/`。

“移除会话及记忆”归档隐藏宿主会话，清理本插件派生数据，不自动备份。导入原件、共享附件、工作区文件和既有备份保留。卸载插件同样保留私人数据；需要迁移或手动备份数据目录时先正常退出 DSH。
